# 交互模型与验收

本文件是对原页的跨组件整理与 Web 可访问性工程补充。单项尺寸/特例按 [页面索引](source-index.md)。

## 先确定状态与提交边界

| 任务 | 草稿 | 提交时机 | 失败与恢复 |
| --- | --- | --- | --- |
| 表单 | 输入过程中本地保留 | 有效提交后请求 | 保留字段，展示字段/全局错误，焦点到首错 |
| 独立开关 | 可乐观变更 | 点击立即请求 | 忙碌防重入，失败回滚并说明 |
| 单选 Select | 无独立确认区 | 选择提交并关闭 | 远程值失败保留上一次有效值 |
| 多选 Select | 选中集合持续可见 | 由表单或单控件契约决定 | 不因搜索词变化或关面板丢选中项 |
| 确认式日期范围 | 暂存起止 | 完整有效且按确定 | 外点/取消撤销草稿；无确认模式另定义 |
| 时间选择器 | 暂存时分 | 确定或外点 | 取消恢复；非法值恢复前值 |
| 上传 | 文件队列 | 真正服务端上传 | 每项进度/错误/重试/取消；失败不删除原文件 |
| 模态编辑 | 输入草稿 | 保存成功后关闭 | 外点/Esc 关闭策略与未保存提示明确 |

以 `idle → pending → success | error` 管理请求；pending 禁止重复提交，error 可重试。加载不要抹掉上下文；只在确无结果且已完成请求后显示 Empty。并发搜索以请求序号或取消机制避免旧结果覆盖新结果。

## 可操作组件状态

Button/Input 等至少按任务覆盖 normal、hover、active、focus-visible、disabled。选择型增加 selected/checked/mixed，输入型增加 invalid/readonly，异步型增加 pending。Disabled 不能只是透明度变化；readonly 仍可聚焦复制。按钮默认 type=button，表单提交明确 type=submit。

## 键盘与焦点

- Button：Tab 到达，Enter/Space 激活；链接 Enter 导航。原生标签和语义优先。
- Checkbox/Switch：Space 改变状态；RadioGroup 箭头切换；混合复选用 `aria-checked=mixed`。
- Tabs：方向键移动，Home/End 首尾；慢内容用手动激活。活动项与面板 ID 关联。
- 菜单：打开聚焦条目，箭头导航、Enter 执行、Escape 返回触发器；子菜单具有明确层级。
- Combobox/Tree：可见焦点与选中值分离；不让输入法回车误提交。复杂键盘模型遵循所用 primitive。
- Modal：提供标题/描述，隔离背景，初始焦点合理，Tab 保持内部，关闭归还触发器。删除确认初始可落在取消。
- Tooltip：hover 和 focus 可见，Escape 关闭，鼠标进入气泡仍保持；带交互内容换 Popover。
- Drag：提供等效移动按钮或快捷键，宣告完成结果；颜色、hover 和拖动都不能是唯一操作线索。

Radix/Base UI 已提供的行为应保留并实际测试。不要在外层重复 keydown 模拟产生双重触发。

## 反馈选择

| 意图 | 组件 | 生命周期 |
| --- | --- | --- |
| 短暂反馈，忽略也不影响任务 | Toast | 无操作默认4秒，有操作至少6秒，悬停/焦点暂停 |
| 上下文持续提醒 | Notice/Alert | 条件解决或允许用户主动关 |
| 系统复杂消息 | Notification | 通常4秒；需要交互时不自动消失 |
| 必须决策 | Dialog/AlertDialog | 用户明确动作后退出 |

Toast 去重，默认可见两条；忙碌信息不能是任务状态的唯一记录。礼貌状态用 role=status，紧急错误才 role=alert；别每输入一个字符都播报。

## 场景验收

- 仅键盘完成主任务，包括打开、取消、重试和关闭；检查焦点归还与浏览器后退。
- 400字译文、长姓名、超长单词、200%缩放、触屏与 RTL 下无关键内容裁切。
- 慢请求、断网、连续双击、部分成功、过期响应、空结果均可辨认并恢复。
- 有效输入不被失败或主题切换丢失。确认文案说清对象和后果。
- 窄屏重排后不改变数据与动作含义；复杂功能若拆出面板，应可发现和返回。

可访问性依据：[WAI-ARIA APG patterns](https://www.w3.org/WAI/ARIA/apg/patterns/)；对比度与焦点按 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 逐项验收。正常文字目标4.5:1，大文字和必要图形/控件边界按适用标准核验3:1；颜色 token 检查不能代替完整合规审查。
